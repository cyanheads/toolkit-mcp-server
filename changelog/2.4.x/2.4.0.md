# 2.4.0 — 2026-11-03

## Added

- **`toolkit-guide` agent skill**, published from root `skills/` and served as the MCP resource `skill://toolkit-guide/SKILL.md` via `createApp({ skills: 'skills' })`, alongside new server `instructions` sent on every `initialize`. The skill also ships in the npm package, the Docker image, and the `.mcpb` bundle.
- **`toolkit_hash_value` computes HMACs** from an optional `secret` and `secretEncoding` (`utf8` default, `hex`, `base64`, `base64url`) for generate and compare; the result carries `hmac: true` and never echoes the secret. `digestEncoding` gains `base64url`; `invalid_secret_encoding` and `sri_with_secret` are new error reasons. [#54](https://github.com/cyanheads/toolkit-mcp-server/issues/54)
- **`toolkit_hash_value` `expected`** also reads a checksum-file line (`<hex>  <file>`, `SHA256 (<file>) = <digest>`), `<algorithm>:` and `<algorithm>=` prefixed digests, and base64url; algorithm names match in any case. A multi-line paste, hex split by whitespace, and a `<hex>  <file>` line whose file name is only hex digits fail as `expected_malformed`. [#53](https://github.com/cyanheads/toolkit-mcp-server/issues/53)
- **`toolkit_encode_value` `outputEncoding: "base64url"`** on decode returns unpadded base64url. [#55](https://github.com/cyanheads/toolkit-mcp-server/issues/55)
- **`toolkit_check_network` `family` input (`4` or `6`)** limits a probe to one address family; a target with no address of that family fails as `family_mismatch`. `ping`, `traceroute`, and `connectivity` results gain `resolvedIp`, the address whose result is reported. [#49](https://github.com/cyanheads/toolkit-mcp-server/issues/49)
- **`toolkit_check_system` `os.runtime` and `os.runtimeVersion`** name the JavaScript runtime (`bun` or `node`) and its version. [#50](https://github.com/cyanheads/toolkit-mcp-server/issues/50)
- **`toolkit_geolocate_ip` `isp`, `asHolder`, and `asName`** sit beside `org`, which can name a customer or sub-allocation rather than the network operator. [#52](https://github.com/cyanheads/toolkit-mcp-server/issues/52)
- **Root `plugin.json` and `mcp.json`** (Agent Plugins 1.0.0 manifests).

## Changed

- **`toolkit_check_network` resolves a hostname once to all its addresses** and tries them in turn, alternating IPv4 and IPv6, until one gives a result. `connectivity`'s `timeoutMs` is one budget shared by every address tried. With `TOOLKIT_ALLOW_PRIVATE_NETWORK` off, private and reserved addresses are skipped, and `private_target_blocked` fires only when none remain. [#49](https://github.com/cyanheads/toolkit-mcp-server/issues/49)
- **`toolkit_check_network` `public_ip`** is described as the host's IPv4 egress address; it cannot show whether IPv6 egress works. [#49](https://github.com/cyanheads/toolkit-mcp-server/issues/49)
- **`toolkit_check_network` `unreachable`** declares DNS failure in every mode, a missing binary, a time-limit kill, and an error exit. [#49](https://github.com/cyanheads/toolkit-mcp-server/issues/49)
- **`toolkit_geolocate_ip` `private_target`** also covers public-format addresses the provider cannot locate. [#51](https://github.com/cyanheads/toolkit-mcp-server/issues/51), [#52](https://github.com/cyanheads/toolkit-mcp-server/issues/52)
- **`toolkit_check_system` memory descriptions** state per platform what `freeBytes`, `usedBytes`, and `availableBytes` count. [#50](https://github.com/cyanheads/toolkit-mcp-server/issues/50)
- **Bun runtime** 1.4.3 → 1.4.4 for package-manager and container pins; `minimumReleaseAge` 3 days → 1 day.
- **Development guidance and tooling** follow the adopted framework: skills, packaging and bundle checks, bug report template.

## Fixed

- **`toolkit_check_network` no longer reads a dual-stack host as down** when the first address the resolver returns has no route (Bun answered with an IPv6 address on a host without an IPv6 route). [#49](https://github.com/cyanheads/toolkit-mcp-server/issues/49)
- **`toolkit_check_system` `memory.availableBytes` under Bun on macOS** is free + inactive + purgeable pages × page size from `vm_stat`, as Node computes it, not free pages alone. A `vm_stat` spawn that fails, including one the OS refuses synchronously, fails as `memory_stats_unavailable`. [#50](https://github.com/cyanheads/toolkit-mcp-server/issues/50)
- **`toolkit_geolocate_ip` provider strings** drop Unicode bidi embedding, override, and isolate controls. [#51](https://github.com/cyanheads/toolkit-mcp-server/issues/51), [#52](https://github.com/cyanheads/toolkit-mcp-server/issues/52)
- **`toolkit_check_network` traceroute `content[]`** shows a silent hop (`*`) as itself, and one hop reads "1 hop".

## Security

- **`toolkit_geolocate_ip` provider-supplied strings** (country, region, city, timezone, ASN, org, and the new fields) render as literal text in `content[]`. [#51](https://github.com/cyanheads/toolkit-mcp-server/issues/51)
- **`toolkit_geolocate_ip` and `toolkit_check_network` error messages** never name a private or reserved address the server's resolver returned; they count such addresses instead. An IP literal the caller sent is still echoed.
