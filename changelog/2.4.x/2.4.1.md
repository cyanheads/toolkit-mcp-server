# 2.4.1 — 2026-11-16

## Changed

- **`toolkit_hash_value` `expected` reads an untagged `<hex>  <file>` line whose file name is only hex digits** (`sha256sum 2026`, `cafe`) as a checksum line, replacing 2.4.0's refusal of every such line. It is read when the first token, after any leading `\`, is 32, 40, 64, 96, or 128 hex characters, and neither the file name's tokens joined nor all tokens joined have one of those lengths; otherwise it fails `expected_malformed`. [#57](https://github.com/cyanheads/toolkit-mcp-server/issues/57)
- **`toolkit_hash_value` fails a line whose first token is another algorithm's digest as `expected_length_mismatch`**, with the hint to retry with that algorithm (`md5sum 2026` under the default `sha256`). [#57](https://github.com/cyanheads/toolkit-mcp-server/issues/57)
- **`toolkit_hash_value` `expected_malformed` gains a hint for a refused hex-named line**: join the digest if it was split by whitespace, or pass the bare digest or `<hex> *<file>`. [#57](https://github.com/cyanheads/toolkit-mcp-server/issues/57)
- **`engines.bun`** `>=1.4.0` → `>=1.4.4`, matching the pinned package manager and the README prerequisite.

## Fixed

- **`toolkit_hash_value` with a non-empty `secret` fails an SRI `expected` (single or multi-entry) or a tagged checksum line (BSD/`--tag` `SHA256 (<file>) = <digest>`, OpenSSL `SHA2-256(<file>)= <digest>`) as `expected_plain_with_secret`**, where 2.4.0 compared it as an HMAC and answered `matches: false`. An HMAC written in those forms is refused too; the same HMAC still matches bare or `<algorithm>=`-prefixed. Untagged lines, prefixed digests, and bare digests compare as HMACs as before. [#59](https://github.com/cyanheads/toolkit-mcp-server/issues/59)
