# 2.3.0 — 2026-09-23

## Added

- **`toolkit_hash_value` `sha384` algorithm** and **`digestEncoding`** (`hex` default, `base64`, or `sri` — `<algorithm>-<base64>`, the npm lockfile `integrity` / Subresource Integrity form; sha256/sha384/sha512 only, else `sri_unsupported_algorithm`). ([#34](https://github.com/cyanheads/toolkit-mcp-server/issues/34))
- **`toolkit_encode_value` `outputEncoding`** (`utf8` default, `hex`, or `base64`) — decode returns the recovered bytes losslessly instead of always re-encoding as UTF-8 text; sent with `encode`, it fails with `output_encoding_not_applicable`. ([#32](https://github.com/cyanheads/toolkit-mcp-server/issues/32))

## Changed

- **`toolkit_hash_value` `expected` is read by shape** — hex, standard base64, or one or more space-separated SRI entries, matched at the algorithm's digest length, so a vendor-published checksum or an npm `integrity` value pastes in as-is. Unrecognizable input now fails `expected_malformed` (previously `expected_length_mismatch`), and an SRI value with no entry for `algorithm` fails `expected_algorithm_mismatch`. ([#34](https://github.com/cyanheads/toolkit-mcp-server/issues/34))
- **`toolkit_hash_value` `operation` no longer defaults to `generate`** — omitted, it resolves to `compare` when `expected` is supplied and `generate` otherwise; sending `expected` together with `operation: 'generate'` is now a typed `expected_without_compare` error rather than a silent ignore. ([#33](https://github.com/cyanheads/toolkit-mcp-server/issues/33))
- **`toolkit_encode_value` decode no longer substitutes `U+FFFD`** — bytes that aren't valid UTF-8 now fail with `decode_not_utf8`; pass `outputEncoding: 'hex'` or `'base64'` to recover them as raw bytes. A `url` escape that isn't UTF-8 (`%FF`) now reports `decode_not_utf8` instead of `decode_failed`. ([#32](https://github.com/cyanheads/toolkit-mcp-server/issues/32))
- **`toolkit_encode_value` ignores whitespace in `hex`, `base64`, and `base64url` decode input**, so line-wrapped MIME and PEM bodies decode; a `url` value is still taken literally. ([#32](https://github.com/cyanheads/toolkit-mcp-server/issues/32))

## Fixed

- **`toolkit_generate_qr` `terminal` format is plain Unicode half-block text** — no ANSI escape codes, fenced in `content[]`, drawn for a dark background (light modules as blocks, dark modules as spaces), and it now honors `margin` instead of a fixed one-module quiet zone. ([#35](https://github.com/cyanheads/toolkit-mcp-server/issues/35))
- **`toolkit_generate_qr` `svg` honors `scale`** — the markup gains `width`/`height` of `(modules + 2 × margin) × scale`; `data_too_large` reports the payload's UTF-8 byte count rather than its character count, and the `png_base64` summary text gains its missing space. ([#35](https://github.com/cyanheads/toolkit-mcp-server/issues/35))
- **`toolkit_generate_id` same-millisecond `uuid_v7`/`ulid` steps are randomized** — the suffix advanced by a constant `+1`, making every id after the first in a batch derivable from any other; it now advances by a random 32-bit draw plus one. ([#39](https://github.com/cyanheads/toolkit-mcp-server/issues/39))

## Dependencies

- `@types/node` (dev) `^26.6.1` → `^26.6.2`
