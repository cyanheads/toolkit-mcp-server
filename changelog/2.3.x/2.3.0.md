# 2.3.0 — 2026-09-23

## Added

- **`toolkit_hash_value` `sha384` algorithm** and **`digestEncoding`** (`hex` default, `base64`, or `sri` — `<algorithm>-<base64>`, the npm lockfile `integrity` / Subresource Integrity form; sha256/sha384/sha512 only).
- **`toolkit_encode_value` `outputEncoding`** (`utf8` default, `hex`, or `base64`) — decode returns the recovered bytes losslessly instead of always re-encoding as UTF-8 text.

## Changed

- **`toolkit_hash_value` `expected` is read by shape** — hex, standard base64, or one or more space-separated SRI entries, matched at the algorithm's digest length, so a vendor-published checksum or an npm `integrity` value pastes in as-is.
- **`toolkit_hash_value` `operation` no longer defaults to `generate`** — omitted, it resolves to `compare` when `expected` is supplied and `generate` otherwise; sending `expected` together with `operation: 'generate'` is now a typed `expected_without_compare` error rather than a silent ignore. ([#33](https://github.com/cyanheads/toolkit-mcp-server/issues/33), [#34](https://github.com/cyanheads/toolkit-mcp-server/issues/34))
- **`toolkit_encode_value` decode no longer substitutes `U+FFFD`** — bytes that aren't valid UTF-8 now fail with `decode_not_utf8`; pass `outputEncoding: 'hex'` or `'base64'` to recover them as raw bytes. ([#32](https://github.com/cyanheads/toolkit-mcp-server/issues/32))

## Fixed

- **`toolkit_generate_qr` `terminal` format is plain Unicode half-block text** — no ANSI escape codes, and `margin` is now honored for every format, not raster output alone. ([#35](https://github.com/cyanheads/toolkit-mcp-server/issues/35))
- **`toolkit_generate_id` same-millisecond `uuid_v7`/`ulid` steps are randomized** — the suffix advanced by a constant `+1`, making every id after the first in a batch derivable from any other; it now advances by a random 32-bit draw plus one. ([#39](https://github.com/cyanheads/toolkit-mcp-server/issues/39))

## Dependencies

- `@types/node` (dev) `^26.6.1` → `^26.6.2`
