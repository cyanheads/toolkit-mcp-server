# 2.3.1 — 2026-09-23

## Added

- **`toolkit_check_network` `connectivity` `outcome`** (`open`, `refused`, `timeout`, or `unreachable`) with the connect time as `rttMs` when open, and **`ping` packet stats** (`sent`, `received`, `packetLossPercent`). ([#37](https://github.com/cyanheads/toolkit-mcp-server/issues/37))
- **`toolkit_check_system` `memory` `availableBytes`/`limitBytes`** — headroom clamped to a container memory limit when one applies; on Bun with no limit, `availableBytes` equals free pages, a known limitation noted in `docs/design.md`. ([#38](https://github.com/cyanheads/toolkit-mcp-server/issues/38))

## Fixed

- **`toolkit_check_network` `ping` reports honest failures** — a binary that never ran or exited without a readable summary (including localized Windows output) now throws `unreachable` naming the binary, with its errno or stderr, instead of reporting `reachable: false`; a Linux run with partial replies that exits 1 now reads `reachable: true`. IPv6 targets on macOS/BSD run `ping6`/`traceroute6`, and the ping spawn timeout now outlasts the ~1 s echo interval, so a Windows run with a short `timeoutMs` is no longer killed mid-way. ([#36](https://github.com/cyanheads/toolkit-mcp-server/issues/36))
- **`toolkit_check_network` caller cancellation propagates** instead of reading as `reachable: false` or `unreachable`, including a cancellation that lands before a `connectivity` probe connects. `connectivity` checks `port` before resolving DNS, a missing `target` or `port` now throws the typed `missing_target`/`missing_port` reason with a recovery hint, and the `unreachable` recovery hint now suggests `connectivity` with a port. ([#36](https://github.com/cyanheads/toolkit-mcp-server/issues/36))
