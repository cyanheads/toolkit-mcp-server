# 2.3.2 — 2026-10-07

## Changed

- **`@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.13** — what clients see:
  - Tool error results close `content[]` with `request <id>` and carry `data.requestId` (0.13.10), a framework-generated token rather than the client's JSON-RPC id (0.13.12).
  - Error `data` no longer carries server stack traces (0.13.7), request-context fields (0.13.8), or `rootCause` (0.13.13).
  - A JSON-stringified object or an integer sent for a string argument is repaired before validation, and argument-rejection hints name the field path (0.13.9).
  - `notifications/message` log lines reach the client only at or above `MCP_LOG_LEVEL`, with sensitive fields masked (0.13.11).
  - MCP SDK `@modelcontextprotocol/server` ^2.0.0 → ^2.2.0 through the framework (2.1.0 in 0.13.9, 2.2.0 in 0.13.11). On the 2026-07-28 protocol revision, a POST without `MCP-Protocol-Version` is refused `400` / `-32020`, and a JSON-RPC batch of more than 100 messages is refused whole.
- **Declared recovery hints** — the framework now fills each tool's declared `recovery` hint from its `errors[]` (0.13.10), so the explicit `ctx.recoveryFor` forwards in the tool handlers and services are removed. Every error result still carries the same hint.
- **Docker `deps` stage** — production dependencies install in a stage pinned to `$BUILDPLATFORM` and cross-install for the target with `--os`/`--cpu`, so the multi-arch build no longer runs `bun install` under QEMU in the production stage. The OTel packages come from `scripts/install-otel.ts`, which reads the framework's `peerDependencies`, replacing a hardcoded `bun add` list.
- **Docker image** — `oven/bun` 1.4.0 → 1.4.2 (build, deps, and slim production stages), and `MCP_FORCE_CONSOLE_LOGGING="true"` is no longer set in the image.
- **`.dockerignore`** — excludes `.env*` and the two `.mcpregistry_*` token files, where it listed five specific `.env` files.
- **`server.json`** — both npm package entries use `runtimeHint` `npx` (was `bun`) and no longer carry the `run start:stdio` / `run start:http` `packageArguments`; the HTTP entry sets `MCP_TRANSPORT_TYPE=http` as an environment variable.
- **`.gitignore`** — ignores `.env*` except `.env.example`, `.env.template`, and `.env.sample` (was `.env`, `.env.local`, `.env.*.local`). **`.mcpbignore`** also excludes `/docs/idea.md` and `/logs/`.
- **`.github/workflows/codeql.yml`** — runs one job per language (`actions`, `javascript-typescript`), each uploading under its `/language:<language>` category, where a single job analyzed both.
- **`package.json`** — `packageManager` `bun@1.4.0` → `bun@1.4.2`, and `files` gains `!dist/*.mcpb`.
- **`README.md`** — capability reference, features, and configuration table condensed; the Docker `run` example drops `-e MCP_TRANSPORT_TYPE=http` (the image sets it); MCP SDK badge ^2.0.0 → ^2.2.0 and Bun badge v1.4.0 → v1.4.2.
- **`CLAUDE.md` / `AGENTS.md`** — synced with the framework template: session-posture and shutdown section, one-workflow CI note, a "Cut noise" rule, a `ctx.clientCapabilities` row, `ctx.recoveryFor` guidance removed, and the skills table and plugin checklist revised.
- **`.env.example`** — documents `MCP_REQUEST_STATE_KEY`, `LOG_TOOL_FAILURE_PAYLOADS`, `LOG_TOOL_FAILURE_PAYLOAD_MAX_BYTES`, `LOG_LLM_INTERACTIONS`, and `OTEL_EXPORTER_OTLP_TRACES_ENDPOINT` / `_METRICS_ENDPOINT` / `_LOGS_ENDPOINT`.
- **`scripts/`** — `devcheck`, `lint-mcp`, `lint-packaging` (adds Dockerfile and `server.json` checks), `release-github` (adds `--check` tag validation), `check-skill-versions`, and `check-framework-antipatterns` synced from the framework.
- **`framework-skills/`** — skill bodies and `metadata.version` synced with the framework.

## Added

- **`scripts/install-otel.ts`** and **`scripts/prune-musl-packages.ts`** — the Docker `deps` stage runs them; the second deletes musl-only native packages from the glibc production image.
