# 2.3.3 — 2026-10-14

## Added

- **`toolkit_geolocate_ip.targets`** accepts up to 1000 inputs, serves the first 100 positions with ordered partial results and recovery, retains duplicates, and discloses every remainder as `unprocessedTargets`. [#40](https://github.com/cyanheads/toolkit-mcp-server/issues/40)
- **`TOOLKIT_GEO_BATCH_RATE_LIMIT_PER_MIN`** sets an independent batch request budget (default 15); cache hits consume no quota.

## Changed

- **Bun runtime** 1.4.2 → 1.4.3 for package-manager and container pins.
- **Development guidance** follows the adopted framework's input repairs, error bounds, canvas constraints, and release procedures.

## Fixed

- **Geolocation quota refusals** declare `rate_limited`, name the wait duration in seconds, and supply recovery guidance. [#45](https://github.com/cyanheads/toolkit-mcp-server/issues/45)
- **Provider HTTP 429** is never retried; independent single/batch cooldowns honor `X-Ttl` and successful `X-Rl: 0`, default invalid resets to 60 seconds, and cap them at one hour. [#47](https://github.com/cyanheads/toolkit-mcp-server/issues/47)
- **Batch correlation** rejects malformed cardinality, status, or mismatched query addresses without misassigning metadata; cached and local outcomes survive provider failures.
- **Windows ping** counts timed IPv4/IPv6 echo replies, excluding ICMP failures from reachability and packet-loss calculations. [#42](https://github.com/cyanheads/toolkit-mcp-server/issues/42)
- **Startup configuration** parses all server settings during framework setup, producing the configuration banner and preserving gated registration after `.env` loading. [#44](https://github.com/cyanheads/toolkit-mcp-server/issues/44)

## Security

- **Provider failure prose** is replaced with server-authored errors on both client response surfaces and notifications, closing the raw `status: "fail"` message injection surface. [#28](https://github.com/cyanheads/toolkit-mcp-server/issues/28)
