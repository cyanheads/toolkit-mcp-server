# 2.2.0 — 2026-08-18

## Added

- **`toolkit_generate_qr` PNG output now returns an MCP image content block** — `png_base64` results add a standard `{ type: 'image', ... }` block to `content[]` via `ctx.content.image`, alongside the unchanged `structuredContent.content` base64 field, so clients that render `content[]` can display the code without decoding structured output. ([#21](https://github.com/cyanheads/toolkit-mcp-server/issues/21))

## Changed

- **`toolkit_generate_id` is now `readOnlyHint: true`** — minting draws from the platform CSPRNG and returns it, modifying nothing; `idempotentHint: false` alone already signals fresh, non-reproducible entropy per call, so the tool no longer buckets with mutating operations that need write approval. ([#19](https://github.com/cyanheads/toolkit-mcp-server/issues/19))

## Fixed

- **`toolkit_check_network`'s `public_ip` mode no longer leaks raw upstream fetch errors** — a failing or malformed `api.ipify.org` response now surfaces a sanitized `serviceUnavailable`, mirroring `GeoService.lookup()`; the original error is preserved only as `cause` for server-side logs. ([#16](https://github.com/cyanheads/toolkit-mcp-server/issues/16))
- **Windows `ping`/`traceroute` now spawn the correct binary and flags** — `win32` uses `ping -n <count> -w <timeoutMs>` and `tracert -d -h 30 -w 1000` instead of the BSD/Linux flag set, which previously made a live host report as unreachable; a hop-address parser bug affecting IPv6 hex-hextet addresses was fixed alongside. ([#17](https://github.com/cyanheads/toolkit-mcp-server/issues/17))
- **`toolkit_check_network`'s `unreachable` errors now carry their declared recovery hint** — hostname-resolution and traceroute-execution failures spread `ctx.recoveryFor('unreachable')`, which required threading `Context` into `NetDiagService.resolve()`; the hint now reaches both `structuredContent.error.data` and the `content[]` error text. ([#23](https://github.com/cyanheads/toolkit-mcp-server/issues/23))

## Security

- **`toolkit_encode_value` decoded output can no longer break out of its Markdown fence** — the response's fence delimiter is now sized one backtick past the longest backtick run in the decoded value, so content carrying its own fence sequence can't terminate the block early and have the remainder read as Markdown. ([#20](https://github.com/cyanheads/toolkit-mcp-server/issues/20))
- **`toolkit_generate_qr`'s `png_base64` raster is now bounded at 2048 px per side** — `data` (via symbol version), `margin`, and `scale` multiply into one raster with no prior combined limit, so a ~3 KB request could render a ~6000 px image and hold a ~180 MB RGBA buffer for the call's duration. Over-budget requests are rejected with a typed `raster_too_large` error naming a `scale` that fits; `svg` and `terminal` carry no such limit. ([#24](https://github.com/cyanheads/toolkit-mcp-server/issues/24))
