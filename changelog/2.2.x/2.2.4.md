# 2.2.4 — 2026-09-19

## Added

- **`inputAliases` on `toolkit_check_network`, `toolkit_encode_value`, `toolkit_generate_qr`, `toolkit_geolocate_ip`, and `toolkit_hash_value`** — an undeclared key naming a common synonym (`ip`/`hostname`/`host` → `target`, `input`/`text`/`data` → `value` or `data`) resolves to the declared key instead of failing as unrecognized ([mcp-ts-core#452](https://github.com/cyanheads/mcp-ts-core/issues/452)). The declared key always wins when both are sent, and `inputSchema` is unchanged. 20 new tests pin this in `tests/tools/wire-contract.test.ts`.
- **`.github/workflows/codeql.yml`** — the framework's default CodeQL workflow, added to the scaffold in mcp-ts-core 0.13.3; runs only while the repo's CodeQL default setup is off.
- **`lint:packaging` check 12 — README version badge parity** — the `Version-<semver>-` badge must match `package.json` `version`.
- **`devcheck.config.json` `lint.truncationAllowlist`** — declares the linter's truncation exemptions in one place instead of an env var per script entry.
- **`package.json` `funding`** — GitHub Sponsors and Buy Me a Coffee entries.
- **`.env.example` documents `MCP_HTTP_RESUMABILITY*` and `MCP_LOG_RATE_LIMIT_*`** — framework env vars this server doesn't otherwise adopt.

## Changed

- **Session mode is declared in source** — `createApp({ sessionMode: 'stateless' })` ([mcp-ts-core#376](https://github.com/cyanheads/mcp-ts-core/issues/376); resolves #27). With `MCP_SESSION_MODE` unset the server resolves `stateless` from `createApp({ sessionMode })`; an explicit `MCP_SESSION_MODE` value still overrides it.
- **Argument rejections carry `data.reason: "invalid_arguments"` and a schema-derived recovery hint, and tool error text closes with `(reason <reason>)`** — inherited from the framework dependency bump ([mcp-ts-core#445](https://github.com/cyanheads/mcp-ts-core/issues/445), [mcp-ts-core#458](https://github.com/cyanheads/mcp-ts-core/issues/458)); verified on this server's own stdio output.
- **Four `errors[]` entries carry `thrownBy: 'service'`** — lint-only metadata marking a reason the service layer raises, so the unthrown-reason lint rule skips the handler-level check for it ([mcp-ts-core#462](https://github.com/cyanheads/mcp-ts-core/issues/462)).
- **`CLAUDE.md`/`AGENTS.md` document the gated release-PR `## Publishing` mode.**
- **`scripts/build.ts`, `scripts/clean.ts`, and `scripts/devcheck.ts` probe both `config/` and root tsconfig layouts**, and `scripts/lint-mcp.ts`/`scripts/lint-packaging.ts` sync to the framework's 0.13.x versions.
- **`framework-skills/` and `changelog/template.md` synced to mcp-ts-core 0.13.1–0.13.6** — mechanical skill-doc updates, no behavior change in this server.
