# 2.2.1 — 2026-08-22

## Changed

- **Framework: `@cyanheads/mcp-ts-core` `^0.11.5` → `^0.12.3`**, replacing the transitive `@modelcontextprotocol/sdk` `^1.30.0` dependency with `@modelcontextprotocol/server`/`@modelcontextprotocol/client` `^2.0.0`. Three client-visible wire changes ship with the bump: tool inputs are now strict at the root — an argument key the schema doesn't declare is rejected by name instead of silently stripped; every tool's advertised `outputSchema` now declares the error envelope; and advertised JSON Schema is emitted as 2020-12 rather than draft-07.
- `tsc-alias` `^1.9.1` → `^1.9.2`, `vitest` `^4.1.10` → `^4.1.11`.
- **Bun pinned to `1.4.0`** (`packageManager`, both `Dockerfile` stages) — matches the pin framework `0.12.3` prescribes; `engines.bun` stays `>=1.3.0`.
- Skills and lint scripts synced to the new framework surface: `ctx.requestInput`/`ctx.inputs` replace the removed `ctx.elicit`/`ctx.progress` in the agent-protocol docs, `scripts/lint-mcp.ts` drops the retired `taskHandlers` tool-detection branch, and `scripts/lint-packaging.ts`'s critical-runtime-path check follows the SDK package rename.
- **`.env.example` sets `MCP_SESSION_MODE=stateless`** as this server's explicit, uncommented default — this server holds no per-session state (seven request/response tools, no resources or prompts), so the `Dockerfile` `ENV` now restates rather than overrides the posture. Declaring it in `src/index.ts` is tracked separately, pending upstream `createApp` support for a `sessionMode` option. ([#27](https://github.com/cyanheads/toolkit-mcp-server/issues/27))

## Security

- **`GeoService.lookup()` and `NetDiagService`'s egress-IP probe route sanitized upstream-failure detail to the process `logger` instead of `ctx.log`.** Framework `0.12.0` made `ctx.log` dual-sink, mirroring every call to the client as `notifications/message`; adopting `^0.12.3` here pairs the bump with this change so the existing `serviceUnavailable` sanitization — provider URL, HTTP status, and up to 500 bytes of upstream body kept out of the thrown error — holds across the new sink too, rather than reaching the client through the log call instead. New tests assert the client-visible log payload never carries the upstream host, status, or body.
