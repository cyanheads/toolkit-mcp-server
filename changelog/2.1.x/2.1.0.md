# 2.1.0 — 2026-08-18

## Added

- **`toolkit_geolocate_ip` proxy/hosting/mobile flags** — surfaces ip-api's `proxy`, `hosting`, and `mobile` booleans on `GeoResult` and in `format()`, so the model can tell when coordinates describe infrastructure rather than a person. Absent when the provider doesn't report them. ([#15](https://github.com/cyanheads/toolkit-mcp-server/issues/15))
- **Public hosted server** at `https://toolkit.caseyjhand.com/mcp` — documented in the README and added to `server.json`'s Streamable HTTP remotes.

## Changed

- **`GeoService` cache is bounded** — capped at 1000 resident entries (`GEO_CACHE_MAX_ENTRIES`) with insertion-order eviction of the oldest entry, so a long-running HTTP deployment geolocating many distinct IPs no longer grows the cache without bound. ([#18](https://github.com/cyanheads/toolkit-mcp-server/issues/18))
- **Geolocation provenance is fixed, not configurable** — `GeoService` always speaks the ip-api request/response protocol against `TOOLKIT_GEO_BASE_URL`, so `source` and the sanitized failure message now report a hardcoded `"ip-api"` rather than an unvalidated env value. ([#22](https://github.com/cyanheads/toolkit-mcp-server/issues/22))
- Framework: `@cyanheads/mcp-ts-core` `^0.10.9` → `^0.11.5`, `@modelcontextprotocol/sdk` `^1.29.0` → `^1.30.0`.
- Docker: multi-stage installs use a BuildKit cache mount for Bun's package cache, and the production/OTEL stages add `--omit=peer` so the framework's optional peer tiers (test runner, service SDKs, parsers) aren't pulled into the image.
- `bunfig.toml` now runs every install through the Socket security scanner (`@socketsecurity/bun-security-scanner`).

## Removed

- **`TOOLKIT_GEO_PROVIDER`** — removed from `server-config.ts`, `.env.example`, `server.json`, and `manifest.json`. It never selected a provider adapter; `GeoService` has only ever spoken the ip-api protocol, so the variable configured nothing beyond the `source` label it could falsify. ([#22](https://github.com/cyanheads/toolkit-mcp-server/issues/22))

## Security

- **IPv6 private/reserved classification flipped from a denylist to an allowlist** — an address is now public only inside `2000::/3`, minus the special-use blocks carved out of it (Teredo, ORCHID/ORCHIDv2, 6to4, documentation, benchmarking, discard-only, NAT64). Unallocated and future-assigned IPv6 space now classifies as reserved instead of silently passing a denylist that forgot to name it, closing a gap where `toolkit_check_network`'s private-range guard and `toolkit_geolocate_ip` could treat unrouted space as a public target. ([#26](https://github.com/cyanheads/toolkit-mcp-server/issues/26))
- **IPv4-mapped IPv6 addresses in hex-hextet form** (`::ffff:7f00:1`) now classify identically to the dotted spelling (`::ffff:127.0.0.1`) — previously only the dotted tail was de-mapped before the IPv4 check, so the hex spelling of the same 32 bits bypassed the private/reserved guard entirely. ([#14](https://github.com/cyanheads/toolkit-mcp-server/issues/14))
- **Provider-supplied strings are bounded and stripped** — `country`, `region`, `city`, `org`, `isp`, `asn`, `timezone`, and the provider failure message are capped at 256 characters and stripped of Unicode control characters (collapsed to a single space, not deleted) before reaching cached or client-facing output. Closes an unbounded-injection path where a compromised or malicious ip-api-compatible endpoint could flood or format-inject a model's context via registry-controlled text. ([#25](https://github.com/cyanheads/toolkit-mcp-server/issues/25))
