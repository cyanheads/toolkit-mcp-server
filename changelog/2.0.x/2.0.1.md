# 2.0.1 — 2026-06-28

## Fixed

- **`toolkit_generate_qr` over-capacity input** — payloads that pass the schema's 2953-byte cap but exceed the QR capacity for the chosen `errorCorrection` level now return a typed `data_too_large` (`InvalidParams`) error with a recovery hint, instead of an untyped internal-error envelope from the `qrcode` library. The `data` description and README clarify that 2953 is the absolute ceiling (version 40, level L, byte mode) and usable capacity drops at higher levels. ([#10](https://github.com/cyanheads/toolkit-mcp-server/issues/10))
- **`toolkit_generate_id` batch ordering** — `uuid_v7` and `ulid` batches are now monotonic: the random suffix increments rather than being redrawn for IDs minted within the same millisecond, so a batch is strictly increasing and lexicographically sorted by creation, matching the advertised time-ordered/sortable contract. `uuid_v4` is unchanged (independent draws, no ordering contract). ([#11](https://github.com/cyanheads/toolkit-mcp-server/issues/11))
- **`TOOLKIT_GEO_RATE_LIMIT_PER_MIN` now enforced** — `GeoService` throttles outbound provider calls through the framework `RateLimiter` (cache hits exempt, since they never reach the upstream); exhausting the per-minute budget returns a retryable `RateLimited` error instead of silently exceeding the keyless free tier. The previously inert env var now governs real behavior, and its descriptions were corrected across the config schema, README, `manifest.json`, and `server.json`. ([#12](https://github.com/cyanheads/toolkit-mcp-server/issues/12))
